## 1. Архитектура двух инстансов на Mac mini

### 1.1 Топология

```
LAN (192.168.x.x / mac-mini.local)
       │
       ├── :80   → prod nginx   → prod backend :8000   → prod БД (moex-sqlite-data)
       │
       └── :8080 → canary nginx → canary backend :8001 → canary БД (moex-sqlite-data-canary)
```

- prod: live-торговля, реальный T-Invest Full-access токен.
- canary: бэктесты + paper-trading + sandbox; Real-account только Readonly (для котировок и виджетов "Реальный портфель").

### 1.2 Структура каталогов в репозитории Develop

```
Develop/
├── docker-compose.yml              (prod, существует)
├── docker-compose.canary.yml       (НОВЫЙ)
├── Dockerfile.backend              (общий)
├── frontend/Dockerfile             (общий, принимает VITE_DEPLOY_MODE ARG)
├── nginx.conf                      (prod)
├── nginx.canary.conf               (НОВЫЙ)
├── backend/.env.production         (prod секреты)
├── backend/.env.canary             (НОВЫЙ canary секреты)
└── scripts/
    ├── deploy.sh                   (НОВЫЙ)
    ├── canary-sync-from-prod.sh    (НОВЫЙ)
    ├── backup-job.sh               (НОВЫЙ)
    ├── backup-rotate.sh            (НОВЫЙ, GFS)
    ├── restore-from-backup.sh      (НОВЫЙ)
    └── watchdog.sh                 (НОВЫЙ)
```

### 1.3 Docker-конфигурация canary

`docker-compose.canary.yml`:

```yaml
services:
  backend-canary:
    image: moex-terminal/backend-canary:current
    container_name: moex-backend-canary
    env_file:
      - ./backend/.env.canary
    environment:
      TZ: "Europe/Moscow"
      DATABASE_URL: "sqlite+aiosqlite:////app/data/app.sqlite"
      TRADING_ENABLED: "false"
    volumes:
      - sqlite-data-canary:/app/data
      - sqlite-backups-canary:/app/backups
    mem_limit: 1g
    cpus: 1.5
    networks:
      - moex-net-canary

  frontend-canary:
    build:
      context: ./frontend
      args:
        VITE_DEPLOY_MODE: canary
    container_name: moex-frontend-canary
    volumes:
      - ./nginx.canary.conf:/etc/nginx/conf.d/default.conf:ro
    ports:
      - "8080:80"
    depends_on:
      backend-canary:
        condition: service_healthy
    networks:
      - moex-net-canary

volumes:
  sqlite-data-canary:
    name: moex-sqlite-data-canary
  sqlite-backups-canary:
    name: moex-sqlite-backups-canary

networks:
  moex-net-canary:
    name: moex-net-canary
    driver: bridge
```

`nginx.canary.conf` — копия `nginx.conf`, но `proxy_pass http://backend-canary:8000` вместо `backend:8000`.

### 1.4 Распределение T-Invest токенов

| Канал | prod | canary |
|-------|------|--------|
| `TINVEST_TOKEN_FULL` (Full-access real) | ✅ | ❌ нет |
| `TINVEST_TOKEN_READONLY` (Readonly real) | — (не используется в prod) | ✅ |
| `TINVEST_TOKEN_SANDBOX_A` | ✅ для paper-fallback | ❌ |
| `TINVEST_TOKEN_SANDBOX_B` (отдельный sandbox для canary) | ❌ | ✅ |

Двухслойная защита от случайной торговли в canary:
1. **T-Invest сторона:** Readonly-токен физически возвращает 403 при попытке `post_order`.
2. **Наш код:** env-флаг `TRADING_ENABLED=false` блокирует попытку до достижения брокера.

### 1.5 Сетевой доступ

- nginx слушает `0.0.0.0` на портах 80 и 8080.
- macOS firewall разрешает входящие соединения на 80 и 8080 для устройств локалки.
- Доступ с iPhone/iPad/ноутбука через `http://mac-mini.local` (Bonjour) или `http://192.168.x.x`.
- Без VPN/Tailscale — доверяем домашней локалке. JWT + Argon2id + rate limit (5 req/min на /auth/login) — достаточная защита от guest-устройств.

### 1.6 Канареечная синхронизация БД prod → canary

`scripts/canary-sync-from-prod.sh`:

1. `docker compose -f docker-compose.canary.yml stop backend-canary`
2. `docker exec moex-backend sqlite3 /app/data/app.sqlite ".backup /tmp/canary-seed.sqlite"`
3. `docker cp moex-backend:/tmp/canary-seed.sqlite ./tmp/canary-seed.sqlite`
4. `docker cp ./tmp/canary-seed.sqlite moex-backend-canary:/app/data/app.sqlite`
5. Очистка чувствительного: `sqlite3 ... "UPDATE live_sessions SET status='cancelled'; DELETE FROM tinvest_connection_state;"` чтобы canary не пытался восстановить live-стрим к real-account.
6. `docker compose -f docker-compose.canary.yml up -d backend-canary`

### 2.2 Guard в адаптере

`backend/app/broker/tinvest/adapter.py::place_order` — в начале метода:

```python
from app.config import settings
from app.broker.exceptions import TradingDisabledError

async def place_order(self, ticker: str, direction: str, ...) -> OrderResponse:
    if not settings.trading_enabled:
        logger.warning(
            "trading_disabled_blocked",
            attempted_ticker=ticker,
            attempted_direction=direction,
        )
        raise TradingDisabledError(
            "TRADING_ENABLED=false; this instance cannot place real orders"
        )
    # ... существующая логика
```

`backend/app/broker/exceptions.py` — новый класс `TradingDisabledError(BrokerError)`.

### 2.3 Что НЕ блокируется

- Sandbox-ордера через `client.sandbox.post_sandbox_order` — виртуальные деньги, остаются доступны.
- Paper-trading — это in-memory симуляция, в T-Invest не идёт.
- Read-методы (`get_candles`, `get_portfolio`, `get_positions`) — необходимы для UI canary.

## 4. Backup-система

### 4.1 Хранилище

- Целевое устройство: USB-флешка (на старте) → USB-SSD 256–500 ГБ (позже).
- Путь конфигурируется через env-var `BACKUP_TARGET_DIR` (например `/Volumes/USB-DRIVE/moex-backups`).
- Смена устройства = смена пути в env, не перекомпиляция.
- Если устройство отключено / target не writable → Telegram-алерт через watchdog-бота, exit 1.

### 4.2 Расписание

- Ежедневно 03:00 МСК (00:00 UTC) через launchd.
- GFS retention: 7 daily + 4 weekly + 12 monthly = 23 копии.

### 4.3 Содержимое архива

```
moex-backup-YYYYMMDD-HHMMSS.tar.gz.enc
├── prod.sqlite         (sqlite3 .backup snapshot)
├── .env.production
├── .env.canary         (если canary существует)
├── docker-compose.yml
├── docker-compose.canary.yml
├── nginx.conf
├── nginx.canary.conf
└── alembic-head.txt    (echo $(docker exec moex-backend alembic current))
```

`canary` БД НЕ бэкапится (по решению заказчика — пересоберётся из prod-снапшота при необходимости).

### 4.4 Шифрование

- AES-256-CBC через `openssl enc -aes-256-cbc -pbkdf2`.
- Пароль хранится в **macOS Keychain** (`security add-generic-password -s 'moex-backup'`).
- Дополнительно заказчик копирует пароль в персональный парольный менеджер (1Password / KeePass).
- При утере Keychain (например после переустановки macOS) восстановление возможно только из парольного менеджера.

### 4.5 Алгоритм backup-job.sh

```bash
1. BACKUP_TARGET="${BACKUP_TARGET_DIR:-/Volumes/USB-DRIVE/moex-backups}"
2. test -d "$BACKUP_TARGET" && test -w "$BACKUP_TARGET" || { telegram_alert "backup target unavailable"; exit 1; }
3. mkdir -p "$BACKUP_TARGET"/{daily,weekly,monthly}
4. TS=$(date -u +%Y%m%d-%H%M%S)
5. WORK=$(mktemp -d)
6. docker exec moex-backend sqlite3 /app/data/app.sqlite ".backup /app/data/snapshot.sqlite"
7. docker cp moex-backend:/app/data/snapshot.sqlite "$WORK/prod.sqlite"
8. cp backend/.env.production backend/.env.canary docker-compose*.yml nginx*.conf "$WORK/"
9. docker exec moex-backend alembic current > "$WORK/alembic-head.txt"
10. tar -czf "$WORK/archive.tar.gz" -C "$WORK" .
11. PASSWORD=$(security find-generic-password -s 'moex-backup' -w)
12. openssl enc -aes-256-cbc -pbkdf2 \
        -in "$WORK/archive.tar.gz" \
        -out "$BACKUP_TARGET/daily/moex-backup-$TS.tar.gz.enc" \
        -pass pass:"$PASSWORD"
13. rm -rf "$WORK"
14. scripts/backup-rotate.sh
```

### 4.6 GFS rotation (backup-rotate.sh)

- `daily/` — оставить последние 7, старше удалить.
- Каждое воскресенье копировать последний daily в `weekly/`; хранить 4.
- 1-го числа каждого месяца копировать последний weekly в `monthly/`; хранить 12.

### 4.7 Restore-сценарий (restore-from-backup.sh)

```bash
1. PASSWORD=$(security find-generic-password -s 'moex-backup' -w)
2. openssl enc -d -aes-256-cbc -pbkdf2 -in "$1" -out /tmp/restore.tar.gz -pass pass:"$PASSWORD"
3. WORK=$(mktemp -d) && tar -xzf /tmp/restore.tar.gz -C "$WORK"
4. INTERACTIVE: показать содержимое + подтверждение "Restore over current prod? (yes/NO)"
5. docker compose down (без -v)
6. Подменить файл в volume moex-sqlite-data на $WORK/prod.sqlite
7. cp "$WORK/.env.production" backend/
8. docker compose up -d
9. curl /api/v1/health → проверить 200 + tinvest_connected
10. Сравнить docker exec moex-backend alembic current с $WORK/alembic-head.txt; при расхождении предупредить
```

Флаг `--auto --target <prod|canary>` для использования из `deploy.sh` (без interactive подтверждения, для rollback).

### 4.8 launchd-plist

`~/Library/LaunchAgents/com.moex.backup.plist` — `StartCalendarInterval` Hour=0 Minute=0 (UTC = 03:00 МСК).

### 4.9 Карточки

- `S8R-W6-SCRIPT-BACKUP` — 5–7 ч (backup-job.sh + backup-rotate.sh + restore-from-backup.sh + manual restore-test).

## 5. Watchdog

### 5.1 Расписание

- launchd-plist `com.moex.watchdog.plist`, `StartInterval = 300` (каждые 5 минут).

### 5.2 Проверки

1. **Backend health** — `GET /api/v1/health` отвечает 200; 3 fails подряд (15 мин) → алерт `backend-down`.
2. **T-Invest connection** — `tinvest_connected == true` в health-ответе; алерт только в торговые часы MOEX (Mon–Fri 10:00–19:00 МСК) → `tinvest-disconnected`.
3. **Live strategies heartbeat** — новый endpoint `/api/v1/admin/strategies/heartbeat` отдаёт `[{name, last_signal_age_minutes}]`. Если `last_signal_age_minutes > 120` в торговые часы → `strategy-silent`.
4. **Backup success** — после 03:30 МСК проверить, что в `$BACKUP_TARGET_DIR/daily/` есть архив с mtime < 1 час. Если нет → `backup-stale`.

### 5.3 Telegram-канал

- **Отдельный watchdog-бот** (не общий notification-бот). Так алерты технического мониторинга визуально отделены от торговых уведомлений.
- Параметры в Keychain: `moex-watchdog-bot` (token), `moex-watchdog-chat` (chat_id).
- Сообщения шлются **напрямую через `https://api.telegram.org/bot$TOKEN/sendMessage`**, не через backend. Это критично — если backend упал, отправка через него тоже упадёт.

### 5.4 Dedup

- Один тип алерта не повторяется чаще 1 раза в 4 часа (state-файл в `~/.moex-watchdog/last-<kind>`).
- При выздоровлении (health снова 200) state-файл удаляется → следующий fail снова даст алерт.

### 5.5 Новый backend endpoint

`GET /api/v1/admin/strategies/heartbeat`:

- Авторизация: `Depends(require_admin)` ИЛИ заголовок `X-Watchdog-Key: <WATCHDOG_API_KEY>` (env-var).
- Тело ответа:
  ```json
  [
    { "id": 1, "name": "MyStrategy", "last_signal_at": "2026-05-13T12:00:00Z", "last_signal_age_minutes": 45 }
  ]
  ```
- Только стратегии в статусе `active` и mode=`live`.
- `last_signal_at`: добавляется новая колонка `strategies.last_signal_at TIMESTAMP NULL` (alembic-миграция). Обновляется в `EventBus.publish` при `event_type='signal'`, на стороне `signal_processor.py` или `notification/event_bus.py`. Это даёт O(1)-чтение на каждом watchdog-tick и избегает ad-hoc запроса по `events`-таблице.

### 5.6 Тесты

`backend/tests/test_admin/test_heartbeat_endpoint.py`:

1. Admin-user (JWT) → 200, корректное тело.
2. WATCHDOG_API_KEY заголовок → 200.
3. Без auth → 401.
4. Non-admin user → 403.

## 6. Deploy script

### 6.1 Интерфейс

```
./scripts/deploy.sh <prod|canary> [--git-ref=<branch|tag>] [--force-trading-hours]
```

### 6.2 Pre-flight

1. Target ∈ {prod, canary}.
2. `docker info` доступен.
3. `git status --porcelain` пуст (или флаг `--dirty`).
4. `$BACKUP_TARGET_DIR` смонтирован и writable.
5. Для prod в торговые часы MOEX (Mon–Fri 10–19 МСК) — interactive confirmation, либо `--force-trading-hours`.
6. Для prod — общая interactive confirmation "Deploy prod from <cur_ref> to <new_ref>. Continue?".

### 6.3 Основной поток

```
1. Pre-deploy backup БД (внеочередной snapshot) → $BACKUP_TARGET_DIR/daily/moex-backup-pre-deploy-$TARGET-$TS.tar.gz.enc
2. Запомнить путь backup в /tmp/moex-rollback-target.
3. docker tag $IMAGE:current $IMAGE:prev
4. git fetch --all --tags; git checkout $GIT_REF (если задан).
5. docker compose -f <compose-file> build <backend-service>
6. docker compose -f <compose-file> up -d <backend-service>
7. docker tag $IMAGE:latest $IMAGE:current
8. Wait health: до 18×5s (90s максимум) до curl /api/v1/health == 200.
9. Smoke check JSON: .status=="ok" && .scheduler_running && (.tinvest_connected || .market_closed).
10. Дополнительный smoke: /api/v1/strategy/list, /api/v1/market-data/sparkline?ticker=SBER, фронтенд /.
11. Для canary: HTML главной страницы должен содержать "CANARY DEPLOYMENT".
12. Success → telegram_alert "✅ Deploy $TARGET OK: $(git rev-parse --short HEAD)"; rm /tmp/moex-rollback-target.
```

### 6.4 Rollback (на любую ошибку)

```
on_error:
  if docker image inspect $IMAGE:prev → docker tag $IMAGE:prev $IMAGE:current; docker compose up -d
  git checkout - (если git был переключён)
  if exists /tmp/moex-rollback-target → restore-from-backup.sh --auto --target $TARGET <path>
  telegram_alert "🚨 Deploy $TARGET FAILED, rolled back to previous image+БД"
  exit 1
```

### 6.5 Особенности по target

- **canary**: автоматический OK на pre-flight confirmation; обязательная проверка banner в HTML.
- **prod**: интерактивные подтверждения; проверка `trading_enabled=true` в health после deploy.

### 6.6 Telegram канал для deploy-уведомлений

- Тот же watchdog-бот (отдельный от notification-бота). Deploy-события и watchdog-алерты идут одним каналом — оба относятся к технической эксплуатации.

### 6.7 Карточка

`S8R-W6-SCRIPT-DEPLOY` — 5–7 ч (включая manual rollback-test на canary).

## 7. macOS Mac mini setup

Физический чек-лист первого запуска (карточка `S8R-W6-MACMINI-SETUP`, 2–3 ч):

1. **Energy:** System Settings → Energy → Prevent automatic sleeping ON.
2. **Date & Time:** Set timezone Europe/Moscow.
3. **Auto-login** (опц., чтобы launchd-jobs стартовали без ручного логина после ребута).
4. **Docker Desktop** установлен и настроен на автостарт при логине.
5. **Firewall:** разрешены входящие 80 и 8080 для всех устройств LAN.
6. **USB-флешка** отформатирована (APFS или exFAT) и смонтирована в стабильную точку (`/Volumes/USB-DRIVE`).
7. **Keychain entries** созданы (через `security add-generic-password`):
   - `moex-backup` — пароль шифрования backup-архивов (32 байта random base64).
   - `moex-watchdog-bot` — token watchdog Telegram-бота.
   - `moex-watchdog-chat` — chat_id для watchdog-алертов.
   - `moex-watchdog-jwt` — JWT service-account ИЛИ `moex-watchdog-api-key` для WATCHDOG_API_KEY.
8. **launchd-plist'ы** скопированы в `~/Library/LaunchAgents/` и загружены через `launchctl bootstrap gui/$UID ~/Library/LaunchAgents/com.moex.*.plist`.
9. **`.env.production` и `.env.canary`** заполнены реальными значениями (не из репо).
10. **Bonjour:** Mac mini имеет имя `mac-mini.local` (System Settings → General → Sharing → Computer Name).

## 14. Out of scope

Эти задачи **намеренно отложены** до момента, когда система пойдёт в production для других пользователей:

- Доменное имя, SSL/HTTPS, Cloudflare Tunnel.
- Real production p95-метрики через `/admin/metrics` Plotly Dash (требуют живого трафика ≥1 нед.).
- Миграция с SQLite на Postgres.
- Multi-tenant архитектура / отдельные user-spaces.
- Self-hosted GitHub Actions runner.
