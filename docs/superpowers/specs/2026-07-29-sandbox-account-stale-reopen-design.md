# S8R-SANDBOX-ACCOUNT-STALE-REOPEN — автопереоткрытие протухшего sandbox-счёта

- **Дата:** 2026-07-29
- **Цикл:** Sprint_8_Review — финальное сведение
- **Карточка:** `Спринты/Sprint_8_Review/backlog.md` → `S8R-SANDBOX-ACCOUNT-STALE-REOPEN` (medium, открыта 2026-07-09)
- **Решение заказчика:** чинить в этом цикле; вариант «автодетект + кнопка в UI»; при протухании **посреди живой сессии — обновить счёт и продолжить торговать**.

## Проблема

Sandbox-аккаунты T-Invest эфемерны: брокер периодически удаляет и пересоздаёт их. Токен остаётся валиден, но `get_accounts()` начинает возвращать **новый** `account_id`. В `broker_accounts.account_id` остаётся старый, и любая sandbox-операция падает:

```
NOT_FOUND '50004' Account not found
```

Наблюдалось вживую 2026-07-09 (`8de9093c-…` → `f925da17-…`). Обход делался вручную — правкой `broker_accounts.id=3.account_id` прямо в БД. Это операционный дрейф, а не дефект W7.

Severity — medium: затронут только sandbox, real и paper не задеты.

## Границы

**В объёме:** sandbox-путь (`BrokerAccount.is_sandbox == True`).

**Вне объёма:** production/real адаптер и paper-движок не изменяются ни одной строкой. Новых `event_type` не заводится (иначе пришлось бы синхронизировать `EVENT_MAP` ↔ `EVENT_TYPE_LABELS` — лишний объём); факт подмены уходит в structlog и в ответ API.

## Архитектура

Новый модуль **`app/broker/sandbox_recovery.py`** — единственное место, знающее про этот дефект.

| Функция | Ответственность |
|---|---|
| `is_account_not_found(exc) -> bool` | Распознать `NOT_FOUND` / код `50004`. Должна срабатывать и на сыром gRPC-исключении SDK, и на обёртке `BrokerError`, в которую адаптер заворачивает всё подряд (`adapter.py` — `except Exception as e: raise BrokerError(f"...: {e}")`). |
| `async refresh_sandbox_account_id(db, account, adapter) -> str \| None` | `adapter.get_accounts()` → взять первый живой sandbox-счёт → записать в `broker_accounts.account_id`, commit, вернуть новый id. Вернуть `None`, если счёт получить не удалось. |

**Почему отдельный модуль, а не метод сервиса.** Потребителей двое — `app/broker/service.py` и `app/trading/engine.py`. `trading` уже импортирует из `broker`; обратная зависимость замкнула бы цикл импортов.

**Создание счёта отдельным вызовом не нужно:** `TInvestAdapter.get_accounts()` (adapter.py:205) уже сам вызывает `open_sandbox_account()`, когда список sandbox-счетов пуст. Новых методов адаптера не добавляем.

## Точки подключения

Все три — строго под `account.is_sandbox`.

1. **`BrokerService`** (баланс, топ-ап): при `NOT_FOUND` обновить `account_id` и повторить операцию **ровно один раз**. Цикла ретраев нет — второй `NOT_FOUND` уходит наружу как ошибка.
2. **`TradingEngine`** (`_resolve_broker_adapter` → `place_order`): обновить `account_id`, **реконсилировать позиции сессии**, повторить ордер один раз.
3. **`POST /api/v1/broker/{account_id}/reopen-sandbox`** — ручное переоткрытие под кнопку UI. Возвращает старый и новый `account_id`.

### Реконсиляция позиций — почему обязательна

Заказчик выбрал «обновить и продолжить торговать». Само по себе это даёт недостоверные цифры: старый счёт удалён брокером **вместе с позициями**, а `PositionTracker` и Circuit Breaker продолжают считать их открытыми. Последствия — SL/TP закрывают несуществующие позиции, CB меряет просадку по мёртвым данным.

Поэтому при подмене счёта сессия приводится к реальности: новый sandbox-счёт пуст → открытых позиций нет → трекинг обнуляется, и торговля продолжается на достоверном состоянии. Это реализация выбранного варианта, а не отступление от него.

## Обработка ошибок

- `refresh_sandbox_account_id` вернул `None` → ведём себя как сегодня: ошибка наружу, `order_error` для сессии.
- Ретрай строго однократный на каждой точке.
- Production-путь не затрагивается: при `is_sandbox == False` код обхода не выполняется вовсе.

## UI

Кнопка **«Пересоздать sandbox-счёт»** на `/broker-settings`, рядом с «Проверить подключение». Рендерится только для аккаунтов с `is_sandbox`. По клику — `POST …/reopen-sandbox`, результат показывается нотификацией Mantine (старый → новый `account_id`).
