# Отчёт о верификации (шаг 2) — отсев ложных срабатываний по P0/P1

**Дата:** 2026-07-06
**Задача:** подтвердить по реальному коду все находки уровня Critical и High, помеченные «не проверялось», чтобы бэклог не содержал ложных срабатываний.

## Метод

- **Critical (P0):** все 7 различных ранее перепроверены вручную по коду при сборке отчёта (см. [code_review_full_report.md](code_review_full_report.md), раздел 3) — все подтверждены.
- **High (P1):** из 69 High верификацию имели 37 (адверсариальная проверка на этапе ревью). Оставшиеся **32 непроверенных High** обработаны на этом шаге:
  - **7 структурных** («god-компонент», отсутствие lazy-load, дублирование, eager-blob) — проверены прямыми измерениями (`wc`, `grep`): факт налицо.
  - **25 багов/уязвимостей** — переданы 3 независимым агентам-верификаторам (read-only), каждый прослеживал трассу по коду и выносил вердикт confirmed / refuted / uncertain.

## Спорные и отклонённые — что именно уточнить

### ⚠️ `FE-STOR-01` — отклонена как High → перемещена в P3 (Low)
**`frontend/src/stores/authStore.ts:69`.** Заявлено: «`logout()` не очищает сторы». По коду `logout()` **очищает** `backgroundBacktestsStore` и `userFavoritesStore` (+ legacy-ключи localStorage). Не очищается `accountSelectionStore`, но это **сделано намеренно** (S7R-хотфикс: выбор счёта должен переживать релогин) и защищено `pickDefaultBrokerAccount` — если сохранённый счёт не в списке нового пользователя, происходит fallback. Остаточный Low-риск: на общем браузере при совпадении id счёт другого пользователя может отобразиться до срабатывания fallback. Ведётся как P3.

### ❓ `FE-NET-04` — переподключение WS фонового бэктеста
**`frontend/src/hooks/useBacktestJobWS.ts:257`.** Формулировка «не переподключается» неточна: reconnect происходит косвенно — эффект по `idsKey` пересоздаёт сокеты для всё ещё активных `job_id` при следующем ре-рендере стора. Чего действительно нет — самостоятельного retry/backoff (в отличие от одиночного `useBacktestJobWS`). Уточнить: достаточно ли косвенного восстановления, или нужен явный backoff.

### ❓ `FE-CHART-01` — VlinePrimitive без sequential-mode
**`frontend/src/components/charts/primitives/VlinePrimitive.ts:27`.** Примитив использует `timeToCoordinate` без ветки `isSeriesInSequentialMode` (в отличие от `coords.ts`), что похоже на реальный пробел (аналог задокументированного `S7R-DRAWING-INTRADAY-COORDS`). Не подтверждено, применяется ли VlinePrimitive для intraday-таймфреймов в проде — проверить точки вызова перед решением.

### ❓ `FE-BTST-15` — rAF-цикл в InstrumentChart
**`frontend/src/components/backtest/InstrumentChart.tsx:289`.** Утечки после размонтирования **нет** — `cancelAnimationFrame` в cleanup присутствует. Остаётся лишняя нагрузка CPU, только если компонент скрывается через CSS `display:none` (а не размонтируется). Уточнить сценарий скрытия; если через unmount — находку можно закрыть.
