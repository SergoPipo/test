# 006: Расширение конструктора стратегий (цена, линии индикаторов, ATR-стопы, мультитаймфрейм)

> **Приоритет:** Высокий
> **Источник:** Sprint 8 Review — рекомендации внешнего AI-помощника по ограничениям блок-схем стратегий
> **Дата:** 2026-06-25
> **Целевой этап:** Sprint 9 (развитие, после сдачи проекта)

---

## Проблема

Текущий конструктор Blockly (20 блоков) ограничивает класс стратегий, которые можно собрать. На уровне UI **нельзя**:

- сослаться на **цену** в условии (`Close < BB_lower`, `High пробил уровень`) — цена доступна только косвенно, как `SOURCE` внутри SMA/EMA;
- использовать **отдельные полосы Bollinger Bands** (Upper/Lower) и отдельные линии MACD (Signal/Hist) и Stochastic (%D) — в условии всегда берётся одна линия;
- привязать стоп к **волатильности (ATR)** — есть только фиксированный процент/пункты;
- вести **трейлинг-стоп**;
- отфильтровать вход по **старшему таймфрейму** (тренд дневного ТФ как фильтр для внутридневной стратегии);
- выразить **импульс / процентное изменение цены** (`Close вырос на X%`).

### Ключевой факт: расчётное ядро уже готово

Ограничения — **не в математике**, а в верхних слоях (UI → парсер IR → точечно evaluator/risk_monitor). Бэкенд уже умеет:

| Возможность | Где реализовано |
|-------------|-----------------|
| `atr()` (Wilder SMMA, паритет с backtrader) | `app/strategy/indicators.py` |
| `bollinger()` → `{mid, top, bot}` (3 линии) | `app/strategy/indicators.py` |
| `macd()` → `{macd, signal, hist}`, `stochastic()` → `{k, d}` | `app/strategy/indicators.py` |
| Чтение любого `source` (open/high/low/close) | `evaluator._series()` |
| Доступ к значению на любом баре `i` (lookback) | `evaluator._val_at()` |
| 8 таймфреймов (1m…M), кэш на каждый | `app/market_data/schemas.py` (enum `Timeframe`) |
| Единый интерпретатор live + backtest (BUG-23) | `app/strategy/evaluator.py` |

Сейчас `_series()` **жёстко возвращает одну линию** для многозначных индикаторов (`bollinger(...)["mid"]`, `macd` без `signal/hist`, `stochastic` без `d`) — это и есть точка доработки, а не отсутствующий расчёт.

### Что невозможно собрать сейчас

- «Купить, когда `Close` пробивает нижнюю полосу BB снизу вверх» (возврат к среднему).
- «Стоп = 1.5 × ATR(14)» — адаптивный риск под волатильность инструмента.
- «Трейлинг-стоп 2 × ATR» — фиксация прибыли при развороте.
- «Входить только если дневной тренд (SMA200 дневного ТФ) вверх».
- «Вход при росте цены на 2% за бар» (импульсный пробой).

## Предлагаемое решение

Пакет разбит на **4 фазы** по возрастанию стоимости и от фундамента. Фазы 1–3 не трогают архитектуру стримов; Фаза 4 — отдельный эпик.

### Фаза 1 — Цена и линии индикаторов (сложность S–M)

**Новый блок «Цена»** (категория «Индикаторы»):

| Поле | Значения | Поведение |
|------|----------|-----------|
| `SOURCE` (dropdown) | Close / Open / High / Low / Volume | Возвращает соответствующую серию OHLCV как «индикатороподобное» значение |

После добавления блока «Цена» **сравнение и пересечение с ценой работают из коробки** — `condition_compare` и `condition_crossover` уже принимают два «индикатора», и цена становится одним из них.

**Выбор линии многозначных индикаторов** — у блоков BB / MACD / Stochastic добавляется dropdown `OUTPUT_LINE`:

| Индикатор | Значения dropdown | Ключ в расчёте |
|-----------|-------------------|----------------|
| Bollinger Bands | Upper / Middle / Lower | `top` / `mid` / `bot` |
| MACD | MACD Line / Signal / Histogram | `macd` / `signal` / `hist` |
| Stochastic | %K / %D | `k` / `d` |

**Изменения ядра:** в `IndicatorRef` добавляется поле `output_line: str | None`; в `_series()` снимается хардкод линии — возвращается выбранная. Дефолт сохраняет текущее поведение (Middle / MACD Line / %K) для обратной совместимости.

### Фаза 2 — Импульс (ROC) (сложность M)

Вместо арифметики в условиях (`Close * 1.02`) добавляется **индикатор Rate of Change** — `ROC(period)` = процентное изменение цены за N баров. Это вписывается в существующую архитектуру индикаторов без усложнения парсера IR.

- `indicators.roc(data, period)` → `list[float | None]`;
- маппинг `indicator_roc → roc` в `ir.py`, ветка в `_series()`;
- блок `indicator_roc` (поля `PERIOD`, `SOURCE`).

Стратегия «цена выросла на 2%» собирается как `ROC(1) > 2`.

### Фаза 3 — Стопы по волатильности (сложность M + L)

Объединяет всю тему динамических стопов (включая трейлинг-стоп, **перенесённый из [001](001_position_aware_strategies.md)**).

**ATR-стоп (M):**
- блок `management_stop_loss` получает режим `TYPE = atr` с множителем `K`;
- `RiskParams.stop_loss_atr_multiplier`;
- на баре входа вычисляется ATR, `SL = entry − K·ATR` (long) / `entry + K·ATR` (short);
- ATR-серия прокидывается в момент привязки SL (`OrderManager._attach_sl_tp`).

**Трейлинг-стоп (L):**
- блок `management_trailing_stop` (отступ `%` или `K·ATR`);
- `RiskParams.trailing_stop_*`;
- `RiskMonitor` становится **stateful per-trade**: хранит max_high/min_low с момента входа, на каждой свече подтягивает стоп в сторону прибыли (никогда против).

### Фаза 4 — Мультитаймфрейм (сложность XL, эпик)

Старший таймфрейм как фильтр тренда. Самая дорогая фаза — затрагивает архитектуру данных и стримов:

- `IndicatorRef` / `Condition` получают поле `timeframe: str | None`;
- `evaluate()` принимает несколько серий свечей с выравниванием (align) старшего ТФ по младшему (без заглядывания в будущее);
- `runtime.py` — подписка на 2 стрима свечей;
- бэктест — multi-data в backtrader, обновление shadow-run паритета.

> **Если фаза 4 окажется слишком крупной** при детальном планировании — вынести её в отдельный пункт backlog (007) и реализовывать независимо.

## Критерии готовности

**Фаза 1:**
- [ ] Блок «Цена» доступен; `Close < BB_lower` и `Close пересекает SMA` собираются и проходят бэктест.
- [ ] Dropdown выбора линии работает для BB/MACD/Stochastic; parity-тест на выбор Upper/Lower полосы BB.
- [ ] Старые стратегии (без `output_line`) дают идентичный результат (обратная совместимость).

**Фаза 2:**
- [ ] Индикатор ROC доступен; `ROC(1) > 2` корректно отрабатывает; parity-тест против эталонного расчёта.

**Фаза 3:**
- [ ] ATR-стоп: `SL = K·ATR` выставляется при входе; parity с backtrader.
- [ ] Трейлинг-стоп: на растущем тренде стоп подтягивается, на развороте фиксирует прибыль; тесты на long и short.

**Фаза 4:**
- [ ] Условие на старшем ТФ фильтрует входы; нет look-ahead bias; бэктест и live дают одинаковые сигналы.

**Общее:**
- [ ] Обновлены `ui_checklist` и E2E-сценарии (полный цикл: описание → запуск → верификация).
- [ ] Обновлены FAQ / руководство пользователя и документация по блокам.

## Риски и ограничения

| Риск | Влияние | Митигация |
|------|---------|-----------|
| Паритет live ↔ backtest (BUG-23) | Любая правка `evaluator`/стопов меняет оба режима сразу | Все изменения — в едином интерпретаторе; обязательные shadow-run parity-тесты. Для трейлинга и мультиТФ паритет проверять сложнее — закладывать доп. время |
| Обратная совместимость | Старые стратегии без новых полей | Дефолты сохраняют текущее поведение (Middle / MACD Line / %K); версионирование при необходимости |
| Stateful-трейлинг | Хранение экстремумов per-trade усложняет `RiskMonitor` | Изолировать состояние в объекте сделки; покрыть юнит-тестами на сценарии тренд/разворот |
| Async-разрыв на мультиТФ | `evaluator` синхронный, мультиТФ требует двух стримов | Вынести Ф4 в отдельный эпик; align старшего ТФ строго по закрытым барам |
| Раздувание палитры блоков | Много новых блоков усложняет UI новичку | Dropdown-подход (выбор линии/источника), а не отдельный блок на каждый выход |
