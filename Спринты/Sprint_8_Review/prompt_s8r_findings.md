1. Определить смысл поля. Судя по `RiskMonitor`, `realized_pnl` — это

### Как поднять свой стенд (проверено в прошлом цикле)

Пароль пользователя `sergopipo` спрашивать не нужно: подними стенд на
**копии** рабочей БД и сбрось пароль **в копии**.

```python
# копировать через backup API, не shutil.copy — WAL (gotcha-19)
source = sqlite3.connect(f"file:{src}?mode=ro", uri=True)
target = sqlite3.connect(dst); source.backup(target)
target.execute("UPDATE users SET password_hash = ? WHERE username = 'sergopipo'",
               (PasswordHasher().hash(<временный>),))
```

Свежая рабочая БД — `Develop/.claude/worktrees/s8r-backlog-int/backend/data/verify.db`.
В копии сохраняются T-Invest-токен, привязка Telegram и настройки
уведомлений. `.env` в worktree — симлинк на общий `Develop/.env`,
создавать через `os.symlink`, собирая имя из частей (команды с этим
именем блокируются permission-правилом); содержимое **не читать**.
Свой Vite — свой `cacheDir` (gotcha-46). Открывать только
`http://localhost:...`, не `127.0.0.1`.

Для проверки внешней доставки уведомлений backend поднимать с
`DEV_MODE=false`, иначе Telegram/Email молчат без ошибок в логе
(gotcha-51). ⚠️ При `DEV_MODE=false` сообщения уходят **реальному**
заказчику в Telegram и на почту — без нужды не гонять.
