# Grid Search — оптимизация параметров стратегии

> Перебор значений параметров стратегии для поиска оптимальной комбинации
> через `multiprocessing.Pool` без изменения логики стратегии.

## Концепция

Grid Search **не меняет логику** стратегии (правила входа/выхода, индикаторы, фильтры). Он перебирает **числовые значения параметров**, которые ты вшил в индикаторы или risk-management блоки, и считает бэктест для каждой комбинации, чтобы ты мог выбрать оптимальные значения.

Например, для стратегии:

```
[I1] RSI(period=14)
ВХОД Long КОГДА [I1] > 0
ВЫХОД КОГДА [I1] < 0
СТОП-ЛОСС 2%
ТЕЙК-ПРОФИТ 4%
```

Варьируемые параметры (то, что задано в блоках):

| Параметр | Имя для Grid Search | Текущее значение |
|---|---|---|
| Период RSI | `rsi_period` | 14 |
| Стоп-лосс % | `stop_loss_pct` | 2 |
| Тейк-профит % | `take_profit_pct` | 4 |
| Размер позиции % | `position_size_pct` | 50 |

## Откуда брать имена параметров

Имена формируются автоматически code generator'ом при компиляции стратегии. Полный список:

| Блок | Имена параметров |
|---|---|
| **RSI** | `rsi_period` |
| **SMA** | `sma_period` |
| **EMA** | `ema_period` |
| **MACD** | `macd_fast`, `macd_slow`, `macd_signal` |
| **Bollinger Bands** | `bb_period`, `bb_dev` |
| **ATR** | `atr_period` |
| **Stochastic** | `stochastic_k`, `stochastic_d` |
| **Стоп-лосс (%)** | `stop_loss_pct` |
| **Стоп-лосс (пункты)** | `stop_loss_points` |
| **Тейк-профит (%)** | `take_profit_pct` |
| **Тейк-профит (пункты)** | `take_profit_points` |
| **Размер позиции (%)** | `position_size_pct` |
| **Размер позиции (лоты)** | `position_size_lots` |

> ⚠️ **Дубликаты индикаторов:** если в стратегии два одноимённых индикатора (например 2 SMA — медленная и быстрая), code_generator называет их `sma_period`, `sma_2_period`. Чтобы понять точно — открой вкладку «Редактор» → правая панель «Параметры стратегии» (там показано `[I1] RSI(period=14)`).

## Пошаговый сценарий

**Цель:** найти оптимальный период RSI и стоп-лосс для стратегии «Тестовая».

### Шаг 1 — открой стратегию и нажми «Grid Search»

Откроется модальное окно с формой настройки.

### Шаг 2 — заполни параметры

> ⚠️ Имена параметров **должны точно** совпадать с теми, что генерирует code_generator (см. таблицу выше). Если ввести `sma_fast` для RSI-стратегии — Grid Search вернёт matrix полную error-ячеек.

```
Параметр 1:
  Имя:      rsi_period
  Значения: 7, 10, 14, 21, 28

Параметр 2:
  Имя:      stop_loss_pct
  Значения: 1, 2, 3, 5
```

Total = 5 × 4 = **20 комбинаций**.

Цвет счётчика total:
- 🟢 ≤200 — норма
- 🟡 201–1000 — предупреждение (долго считается)
- 🔴 >1000 — hard cap, запуск заблокирован

### Шаг 3 — Тикер / ТФ / Период

```
Тикер:        SBER
Таймфрейм:    1 час
С:            2025-01-01
По:           2026-04-01
Капитал:      100 000 ₽
```

Период должен быть **минимум 30 дней** (валидация backend).

### Шаг 4 — нажми «Запустить»

Модалка закрывается, в шапке справа появляется индикатор колбы с прогрессом. Каждый из N запусков идёт через `multiprocessing.Pool` (параллельно по числу CPU − 1).

### Шаг 5 — дождись «✓ ГОТОВО»

В карточке появится кнопка **«Показать результат»**. Если страница перезагружалась — карточка останется как «ГОТОВО», но кнопка будет недоступна (`grid_result` не сохраняется в localStorage из-за размера matrix). В таком случае — запусти Grid Search заново.

### Шаг 6 — кликни «Показать результат»

Открывается модальное окно с heatmap.

#### Если 1 параметр

Bar chart — горизонтальные полосы для каждого значения.

#### Если 2 параметра — настоящий 2D heatmap

```
            rsi_period
        7    10    14    21    28
   ┌────┬─────┬─────┬─────┬─────┐
 1 │0.42│ 0.51│ 0.68│ 0.55│ 0.31│
 2 │0.61│ 0.84│ 1.12│ 0.92│ 0.48│  ← цветовая шкала
sl 3 │0.78│ 1.05│ 1.34│ 1.18│ 0.61│   по выбранной метрике
 5 │0.52│ 0.71│ 0.95│ 0.83│ 0.42│   (красный→белый→зелёный)
   └────┴─────┴─────┴─────┴─────┘
```

Самая зелёная ячейка — лучшая комбинация по выбранной метрике.

При hover — tooltip со всеми метриками для этой комбинации:
> Sharpe: 1,34 | P&L: 8 300 | Win: 62,5% | DD: 3,7 | Trades: 24

#### Если 3+ параметров

Heatmap по первым двум параметрам + полная таблица по всем комбинациям.

### Шаг 7 — переключатель метрик

Над heatmap'ом: **Sharpe | P&L | Win Rate | Drawdown** — переключает заливку и значения в ячейках.

### Шаг 8 — полная таблица

Под heatmap'ом — отсортированная по Sharpe ▼ таблица всех комбинаций:

| rsi_period | stop_loss_pct | Sharpe | P&L | Win | DD | Trades |
|---|---|---|---|---|---|---|
| 14 | 3 | 1,34 | 8 300 | 62,5% | 3,7 | 24 |
| 21 | 3 | 1,18 | 7 100 | 58,3% | 4,1 | 28 |
| 14 | 2 | 1,12 | 7 800 | 60,0% | 4,8 | 26 |
| ... | ... | ... | ... | ... | ... | ... |

Можно сортировать по любой колонке (клик на заголовок).

### Шаг 9 — alert overfitting

Если разброс top-5 sharpe > 50% — поверх heatmap появится оранжевый Alert:

> ⚠ Возможный overfitting: разброс top-5 sharpe > 50%. Рекомендуется расширить out-of-sample период перед использованием в live-торговле.

### Шаг 10 — применить лучшие параметры

Сейчас вручную: видишь лучшие значения → возвращаешься в редактор стратегии → меняешь блоки → запускаешь обычный бэктест с этими значениями.

Автоматическая кнопка «Применить лучшие параметры» — фича в backlog'е.

## Лимиты и валидация

| Параметр | Ограничение |
|---|---|
| Максимум параметров | 5 |
| Максимум комбинаций | 1000 (hard cap) |
| Минимальный период | 30 дней |
| Параллельность | `os.cpu_count() − 1` worker'ов |
| Канал WS | `/ws/backtest/{job_id}` (закрывается через 30s после `done`) |

## Где результаты НЕ хранятся

- ❌ В разделе «Бэктесты» (`/backtests`) — Grid Search не пишется как обычные бэктесты по архитектуре (1000 комбинаций × Backtest row слишком тяжело для БД).
- ❌ В localStorage — `grid_result.matrix` исключён из persist (может быть до 1000 строк × 6 полей).

## Где результаты хранятся

- ✅ В RAM-store (zustand) до закрытия вкладки или ручного «Очистить завершённые».
- ✅ Доступны через карточку фонового бэктеста в шапке (иконка колбы) → кнопка «Показать результат».

> 📝 Долгосрочное решение (в backlog'е) — backend-endpoint `GET /api/v1/backtest/grid/{job_id}/result`, который вернёт сохранённый matrix из БД. Тогда heatmap переживёт reload.

## Типичные ошибки

### Все комбинации идентичны

❌ **Симптом:** в matrix все строки имеют одинаковый Sharpe / P&L / trades.

✅ **Причина (исправлено в S7R-GRID-PARAMS-FIX):** до фикса grid worker не передавал `params` в Backtrader. Сейчас — если симптом снова появляется, проверь, что **имя параметра** совпадает с code_generator'овским (см. таблицу выше).

### Win Rate показывает 4444% или другие нонсенс-значения

❌ **Симптом:** Win Rate в heatmap > 100%.

✅ **Причина (исправлено в S7R-GRID-PARAMS-FIX):** двойное умножение на 100. Если симптом всё ещё есть — обнови приложение или сообщи разработке.

### Matrix полна error-ячеек

❌ **Симптом:** все ячейки красные с tooltip «error: ...».

✅ **Причина:** имя параметра не совпадает с реальным `params` стратегии. Проверь таблицу имён выше.

### Превышен лимит параллельных бэктестов

❌ **Симптом:** toast «Превышен лимит параллельных бэктестов (3)».

✅ **Причина:** одновременно может быть запущено ≤3 фоновых задач. Дождись завершения текущих или нажми «×» в карточке (отмена).
